Methodology

How PriceLens stays reproducible

Source and mapping

Official catalogue

PriceCatcher monthly Parquet snapshots are preserved as raw inputs. Official item and premise lookup tables map stable item codes, units, premises, states, and districts before metrics are calculated.

View official catalogue ↗

Calculation rules

Complete observations

Item prices use observed medians with deterministic minimum and maximum values. A basket is the unweighted sum of its component medians, and areas missing any component are excluded rather than treated as zero.

Time and storage

Compact rolling summaries

Raw source Parquet files are preserved before transformation. The free-tier Supabase serving layer stores compact daily area and premise summaries for up to 14 calendar days, and six months of monthly summaries. The dashboard uses the latest available seven-calendar-day observation window.

Data quality

Coverage, not confidence

Coverage quality is described using observed days, complete items, premises, and missingness. These are operational indicators, not statistical confidence intervals.

Waiting for live quality indicators.

Pipeline architecture

ETL, built for a free tier

PriceCatcher files are extracted and preserved, transformed by the Python pipeline in GitHub Actions, then loaded as compact summaries into Supabase. Source snapshots are hashed and summary loads use stable keys and upserts, so reruns remain incremental, idempotent, and reproducible.

AI boundary

Gemini explains, code calculates

When enabled, the Gemini API receives structured, validated summaries only and explains the metrics in plain language. Code calculates every price statistic; if Gemini is unavailable, the dashboard uses a deterministic rule-based fallback.

Technical methodology

How to read coverage

The latest-observation view uses seven inclusive calendar dates ending at the newest date available, but may contain fewer observed dates because PriceCatcher is not a guaranteed daily feed. State baskets can combine premises; premise baskets require all 10 items at one premise. Min, median, and max use the same filtered item population, while basket extrema are component-wise bounds. Dashboard and AI share a deterministic metric snapshot ID.

Monthly fallback wording applies only to the monthly view when its latest month is incomplete. Invalid records are excluded from metrics, suspicious extremes are flagged for review, and raw Parquet is preserved.

Read the technical methodology notes ↗

Known limitations: coverage varies by place and day; prices are observed medians, not guaranteed store prices or a replacement for CPI.
